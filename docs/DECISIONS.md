# 开发决策记录

## 2026-10-14

### 使用 Electron

界面选型必须与“客户端”强关联。Electron 能直接提供 Windows 文件对话框、拖放路径、进程控制、任务栏与打包能力，并能用安全的 preload 边界把 React 与系统能力隔离。

### 预设优先，不直接暴露命令行

普通用户先选择“通用、节省空间、网页、提取音频”等用途。高级区仅展示将使用的 FFmpeg 参数，首版不允许自由编辑。

### 使用自建 CSS 设计令牌替代 Tailwind

实现阶段需要精确控制 960 × 640 桌面窗口、固定底部操作栏和高密度队列。自建令牌和语义类可以减少依赖，并让离线桌面包的样式来源更明确。该调整不改变原方案的交互和视觉目标。

### FFmpeg 与 ffprobe 随应用分发

用户不应先配置环境变量。开发依赖使用 `ffmpeg-static` 与 `@ffprobe-installer/ffprobe`，打包前复制到固定的 `resources/bin`，运行时只解析该受控位置。

### 输出采用临时文件与完成校验

直接写最终文件会让中断后的残缺文件看起来像成功结果。FrameFlow 先写 `.part` 文件，验证时长后再改名；取消和失败会清理临时文件。

### 顺序队列作为 MVP 默认

视频转码通常占满 CPU/GPU。首版一次只转换一个任务，行为更可预测，也更符合普通电脑的散热和响应性要求。

### 浏览器模式只用于界面验收

当普通浏览器中不存在 preload API 时，开发入口注入可预测的模拟数据，便于 Playwright 验收视觉、队列和状态流。Electron 正式构建始终使用真实 preload 与主进程服务。

### 沙箱 preload 固定构建为 CommonJS

Electron 的沙箱 preload 使用受限加载环境。项目将 preload 明确输出为 `index.cjs`，Main 进程也只加载该文件；Electron 环境若没有成功暴露 `window.frameFlow`，Renderer 会直接停止并报告错误，不再静默退回浏览器模拟 API。这样文件与文件夹对话框失效时不会被假数据掩盖。

### 打包依赖只在开发分支解析

`ffmpeg-static` 和 `@ffprobe-installer/ffprobe` 只用于开发环境及打包前二进制暂存，因此归入 `devDependencies`。正式客户端直接从 `resources/bin` 读取 FFmpeg 与 ffprobe，避免把包管理器目录结构和重复二进制带进成品。

### v0.1.0 采用未签名 Windows 包

首版生成 NSIS 安装版与 portable 便携版。当前未配置商业代码签名证书，因此禁用 electron-builder 的签名和可执行文件资源编辑步骤；这避免把证书和系统级符号链接权限作为 MVP 构建前置条件。代价是使用默认可执行文件图标，并且 Windows 可能显示未知发布者提示。正式对外分发时应补充品牌图标与代码签名。

### 正式包必须做端到端媒体验收

仅在源码环境验证 FFmpeg 不足以证明安装包可用。项目新增 `test:packaged`，直接启动 `release/win-unpacked/FrameFlow.exe`，验证打包内工具路径、视频信息和缩略图、选择文件与输出目录 IPC、打开位置调用，以及 H.264、H.265、VP9、MP3 四种输出的实际编码结果。

### 第三方评审后的 P0/P1 加固

用户提供的评审指出 IPC 信任、Windows 取消、Main 并发保护、输出完整性和大文件边界。实施时确认 Renderer 原本已经串行处理队列，但 Main 仍需独立强制并发数为 1，避免绕过 UI 后并行启动。取消统一改为 Windows 进程树终止；通用 `openPath` 被移除，“打开位置”只能定位本次成功输出。输入在 ffprobe 前完成绝对路径、扩展名、文件类型、大小和目录写权限验证，输出增加轨道、编码、分辨率及帧率校验。

缩略图继续使用输入前快速 seek，因为预览响应速度优先于精确到帧；商业发行所需的 FFmpeg 许可证、专利和代码签名审核仍作为发行流程，而不是用代码结论替代。
