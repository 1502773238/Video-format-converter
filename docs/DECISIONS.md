# 开发决策记录

## 2026-10-14

### 使用 Electron

界面选型必须与“客户端”强关联。Electron 能直接提供 Windows 文件对话框、拖放路径、进程控制、任务栏与打包能力，并能用安全的 preload 边界把 React 与系统能力隔离。

### 预设优先，不直接暴露命令行

普通用户先选择“通用、节省空间、网页、提取音频”等用途。高级区仅展示将使用的 FFmpeg 参数，首版不允许自由编辑。

### 使用自建 CSS 设计令牌替代 Tailwind

实现阶段需要精确控制 960 × 640 桌面窗口、固定底部操作栏和高密度队列。自建令牌和语义类可以减少依赖，并让离线桌面包的样式来源更明确。该调整不改变原方案的交互和视觉目标。

### FFmpeg 与 ffprobe 随应用分发

用户不应先配置环境变量。开发依赖使用 `ffmpeg-static` 与 `@ffprobe-installer/ffprobe`，打包前复制到固定的 `resources/bin`，运行时只解析该受控位置。

### 输出采用临时文件与完成校验

直接写最终文件会让中断后的残缺文件看起来像成功结果。FrameFlow 先写 `.part` 文件，验证时长后再改名；取消和失败会清理临时文件。

### 顺序队列作为 MVP 默认

视频转码通常占满 CPU/GPU。首版一次只转换一个任务，行为更可预测，也更符合普通电脑的散热和响应性要求。

### 浏览器模式只用于界面验收

当普通浏览器中不存在 preload API 时，开发入口注入可预测的模拟数据，便于 Playwright 验收视觉、队列和状态流。Electron 正式构建始终使用真实 preload 与主进程服务。

### 当前环境问题

Electron 33 Windows 运行时约 110 MB，当前网络下载速度异常缓慢。生产构建、真实 FFmpeg 媒体链路和基于 Edge 的界面验收均可继续；原生 Electron 冷启动和安装包测试须在运行时下载完成后补做。
