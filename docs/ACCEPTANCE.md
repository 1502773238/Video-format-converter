# FrameFlow 使用与验收手册

## 1. 环境准备

推荐使用 Windows 10/11 x64、Node.js 20 LTS 或更高版本、pnpm 11。

打开 PowerShell：

```powershell
git clone https://github.com/1502773238/Video-format-converter.git
cd Video-format-converter
corepack enable
pnpm install
```

首次安装需要下载 Electron、FFmpeg 和 ffprobe。若下载速度较慢，可稍后重新执行 `pnpm install`，不要手工把未知来源的可执行文件复制进项目。

## 2. 启动应用

启动真实 Electron 客户端：

```powershell
pnpm dev
```

只查看界面，不调用真实文件系统和 FFmpeg：

```powershell
pnpm dev:renderer
```

浏览器打开 `http://127.0.0.1:5173/`。此模式会载入两条模拟任务，仅用于界面预览。

## 3. 基本使用

1. 点击拖放区域选择视频，或把视频直接拖入窗口。
2. 检查缩略图、时长、分辨率、帧率、编码、码率和轨道数量。
3. 为每个任务选择用途：
   - 通用 MP4：优先兼容手机、电脑、电视和社交平台。
   - 高压缩 MP4：H.265，文件通常更小，但老设备兼容性较弱。
   - 网页 WebM：VP9 + Opus。
   - 提取 MP3 音频：只保留音频。
4. 可选“选择文件夹”；不选择时输出到源文件目录。
5. 点击“开始转换”，观察进度和速度。
6. 完成后点击“打开位置”检查输出文件。

输出默认命名为 `原文件名-converted.扩展名`。如已存在同名文件，会生成 `-converted-2`、`-converted-3`，不会覆盖已有文件。

## 4. 自动化验收

依次执行：

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm test:media
```

通过标准：

- 四条命令退出码均为 0。
- 单元测试显示全部通过。
- `out` 目录生成 Main、Preload 和 Renderer 构建结果。
- 媒体冒烟测试输出 H.264 源文件、JPEG 缩略图和 VP9 WebM，并显示大于 0 的时长。

## 5. 人工验收清单

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 单视频导入 | 选择一个 MP4/MOV/MKV | 显示缩略图和媒体信息，不需要填写技术参数 |
| 中文路径 | 导入中文文件名视频 | 正常读取、转换和打开位置 |
| 批量任务 | 一次添加两个视频 | 左侧出现两个任务，按顺序转换 |
| 独立预设 | 两个任务分别选择 WebM 和 MP3 | 切换任务后各自选项保持不变 |
| 取消 | 转换中点击取消 | 当前任务变为已取消，临时文件被清理，队列继续 |
| 同名保护 | 对同一文件连续转换两次 | 第二次生成带数字后缀的新文件 |
| 输出验证 | 播放转换后文件 | 时长正常、画面可播放、音频存在；MP3 场景只检查音频 |
| 最小窗口 | 将窗口缩到 960 × 640 | 底部操作按钮始终可见，无页面级横向滚动 |
| 损坏文件 | 导入非媒体文件或损坏视频 | 显示可理解的错误，不产生成功文件 |

建议使用 10～30 秒的测试视频先验收，再使用大文件测试长任务进度和取消。

## 6. 打包验收

```powershell
pnpm package:win
```

预期在 `release` 目录生成 Windows x64 安装版和免安装版。需要检查：

1. 在未安装 FFmpeg 的 Windows 电脑上仍能读取和转换视频。
2. 安装路径、视频路径和输出路径包含中文时工作正常。
3. 安装、卸载和免安装版启动正常。
4. Windows 可能对未签名安装包显示信誉提示；正式分发前应配置代码签名。

当前仓库尚未提供已签名的 Release 安装包，源码运行和自动化测试可直接验收。
