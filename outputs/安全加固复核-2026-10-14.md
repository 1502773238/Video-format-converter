# FrameFlow 安全与稳定性加固复核

日期：2026-10-14  
范围：用户提供的第三方仓库评审中 P0、P1 与相关工程风险

## 执行结论

评审提出的进程取消、IPC 输入信任、Main 端并发保护、输出结构校验和超大文件边界均已完成代码加固，并通过单元测试、生产构建、真实媒体冒烟测试和打包后 Electron 端到端测试。

没有发现可通过网络远程利用的 Critical 漏洞；FrameFlow 是本地离线桌面应用，不包含账号、Cookie、远程 API 或第三方脚本。主要风险边界是 Renderer 到 Main 的 IPC 权限，以及 Main 对本地路径和 FFmpeg 子进程的控制。

## 逐项处理

### FF-SEC-001：IPC 参数与调用来源验证

- 原级别：P0 / High（Renderer 被攻破时）
- 位置：`src/main/index.ts:26`、`src/main/index.ts:37`、`src/main/index.ts:94`
- 原问题：Main 直接接收 Renderer 传来的路径和转换对象。
- 修复：每个 IPC handler 校验调用者必须是当前主窗口 main frame；转换请求执行运行时结构校验；媒体文件和输出目录必须是绝对路径、存在且类型正确。
- 纵深防护：限制窗口跳转和外部 URL；移除未使用的通用 `openPath` IPC。
- 状态：已修复。

### FF-SEC-002：任意本地路径打开能力

- 原级别：High
- 位置：`src/main/index.ts:131`、`src/main/conversion-service.ts:177`
- 原问题：preload 曾暴露通用 `openPath(path)`，并允许 Renderer 要求 Explorer 定位任意路径。
- 修复：删除 `openPath`；“打开位置”只接受当前 ConversionService 成功生成并登记的输出文件。
- 状态：已修复。

### FF-STAB-001：Windows 取消只终止单进程

- 原级别：P0 / Medium
- 位置：`src/main/utils/process-tree.ts:3`、`src/main/conversion-service.ts:169`、`src/main/utils/run-command.ts:41`
- 原问题：`child.kill()` 不保证终止 Windows 子进程树。
- 修复：Windows 使用参数数组调用 `taskkill /pid <pid> /T /F`，其他系统使用 `SIGTERM`；取消、超时和输出超限统一使用进程树终止器。
- 验证：正式包真实启动 H.265 转换后取消，返回“任务已取消”，无 `.part` 文件残留。
- 说明：FFmpeg 编码器通常是线程而非独立子进程，但进程树终止可覆盖滤镜或外部工具未来可能创建的后代进程。
- 状态：已修复。

### FF-STAB-002：Main 端缺少并发闸门

- 原级别：P0 / Medium
- 位置：`src/main/conversion-service.ts:93`
- 评审修正：正常 UI 已通过 `for...of + await` 串行执行，并不会同时启动十个 FFmpeg；评审所说“没有队列”只对 Main 边界部分成立。
- 修复：Main 在媒体探测前即登记活动任务，强制并发数为 1；取消也能覆盖“正在探测、尚未启动 FFmpeg”的阶段。
- 状态：已修复。

### FF-VALID-001：输出只校验时长

- 原级别：P1 / Medium
- 位置：`src/main/conversion-service.ts:55`
- 修复：除时长外，按预设检查视频/音频轨道、目标编码、分辨率、帧率和 MP3 无视频轨道要求。源文件存在音频时，视频预设必须保留音频。
- 边界：没有自动判断“画面内容是否黑屏”。黑屏可能是合法素材，强制 `blackdetect` 容易误杀；内容质量分析留作可选专业检测功能。
- 状态：结构完整性已修复；内容语义检测不纳入 v0.1.0。

### FF-VALID-002：输入路径和文件大小无边界

- 原级别：P1 / Medium
- 位置：`src/main/validation.ts:5`、`src/main/validation.ts:33`
- 修复：在启动 ffprobe 前检查绝对路径、真实文件、支持的扩展名、非空文件和 500 GB 硬上限；输出目录必须存在、是目录且可写。
- 状态：已修复。

### FF-PERF-001：缩略图快速 seek 精度

- 原级别：P2 / Low
- 结论：保留 `-ss` 位于 `-i` 前的快速 seek。普通用户更需要快速出现预览；少数长 GOP 文件截帧位置轻微偏差不会影响转码正确性。
- 后续：如增加逐帧截图或专业模式，再提供准确 seek。
- 状态：接受现状，不属于缺陷。

### FF-LEGAL-001：FFmpeg 许可证、专利和签名

- 原级别：发布阻塞项
- 结论：代码无法替代法律与发行审核。仓库已保留 `THIRD_PARTY_NOTICES.md`，但商业收费前仍需根据实际 FFmpeg 构建配置完成许可证、源码提供义务、H.264/H.265/AAC 专利与 Windows 代码签名审核。
- 状态：MVP 已披露；商业发布前必须另行完成。
