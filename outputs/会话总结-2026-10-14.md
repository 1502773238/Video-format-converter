# FrameFlow 开发会话总结

日期：2026-10-14  
阶段：v0.1.0 MVP 功能冻结并完成正式包验收

## 1. 用户目标与反馈记录

用户要求开发一个真正给人使用的视频格式转换器，并明确提出：

1. 加载并展示视频信息和缩略图。
2. 允许通过 FFmpeg 命令行完成转换，不要求接入 FFmpeg API。
3. 在基础需求上主动做产品优化。
4. 会话完成后生成 Markdown 总结，记录开发决策和反馈。
5. 完成后提交 GitHub，并把项目链接发回 Boss 直聘 HR 会话。
6. 审核优先关注界面选型，技术方案必须与桌面客户端强关联。
7. 产品必须可理解、可操作并经过实际测试。
8. 按既定方案开始实施，架构与代码需符合规范的软件工程原则。
9. 实际运行反馈指出“任务队列添加”和“确认输出位置选择文件夹”不可用，要求继续修复。
10. 询问除 MP4 外是否需要更多格式，随后要求优先保证当前版本完整，因此本轮冻结功能范围，不再扩展格式。
11. 提供第三方仓库评审，重点指出 IPC 安全、FFmpeg 进程树取消、Main 端队列约束、输出完整性和大文件边界，要求据此继续检查项目。

本阶段没有收到要求推翻既定选型的反馈，因此继续采用 Electron 桌面客户端方案。第 9 项反馈已定位为沙箱 preload 构建格式与引用扩展名不匹配，并完成修复与正式包复验。

## 2. 实施前确认结论

不阻塞本地实现的默认项：

- 首版平台：Windows 10/11 x64。
- 暂定产品名：FrameFlow。
- 技术栈：Electron + React + TypeScript + Vite + Zustand。
- 所有媒体处理在本机完成，不上传云端。
- 普通用户使用用途预设，高级参数默认折叠。
- 批量任务按顺序执行，避免抢占过多 CPU。
- 输出文件不覆盖原文件或已有文件。

项目已按用户提供的公开仓库 `https://github.com/1502773238/Video-format-converter` 实施，v0.1.0 继续使用 FrameFlow 作为产品名。当前环境没有 Boss 直聘连接能力，因此项目链接需要由用户复制发送给 HR。

## 3. 已完成实现

- 建立 Electron 主进程、preload 安全桥和 React Renderer 三层结构。
- 启用 `contextIsolation`、`sandbox`，禁用 Renderer 的 Node.js 能力。
- 实现文件选择、输出目录选择、拖放导入和批量任务队列。
- 使用 ffprobe JSON 读取格式、大小、时长、分辨率、帧率、编码、码率、音轨和字幕轨。
- 使用 FFmpeg 截取视频约 10% 位置作为缩略图。
- 实现通用 MP4、H.265 MP4、WebM、MP3 提取四种预设。
- 使用 FFmpeg `-progress pipe:1` 读取结构化进度和速度。
- 实现取消、同名文件避让、临时文件、输出校验和完成后原子改名。
- 完成空状态、媒体工作区、队列状态、错误状态和完成状态的桌面界面。
- 增加模拟桌面 API，仅供浏览器界面自动化验收使用。
- 增加固定二进制暂存脚本，确保 pnpm 软链接布局不影响 Windows 打包资源。
- 修复沙箱 preload 的 CommonJS 构建与 Main 引用，恢复真实文件和文件夹对话框。
- 将正式包运行时工具解析固定到 `resources/bin`，避免重复打包开发依赖。
- 生成 Windows x64 NSIS 安装版和 portable 免安装版，并记录 SHA-256。
- 增加正式包端到端验收脚本，直接启动成品客户端验证四种预设。
- 为所有 IPC handler 增加主窗口 main frame 来源校验和运行时参数校验。
- 移除通用本地路径打开能力，“打开位置”只允许本次成功转换的输出。
- 增加 Windows FFmpeg 进程树终止，并覆盖取消、超时和输出超限场景。
- Main 进程强制同一时间只接受一个转换任务，且取消可覆盖媒体探测阶段。
- 输入在 ffprobe 前检查绝对路径、扩展名、文件类型、非空、500 GB 上限和输出目录写权限。
- 输出校验扩展为时长、轨道、编码、分辨率与帧率检查。
- 新增安全加固复核文档与 6 条 Main 端加固测试。
- 编写 README、架构说明、决策记录、MIT License 和第三方依赖提醒。

## 4. 开发者决策与理由

| 决策 | 理由 |
|---|---|
| Electron 桌面客户端 | 与文件系统、子进程、窗口和 Windows 打包直接关联，符合界面审核要求。 |
| Renderer 不直接运行 FFmpeg | 通过 preload 白名单和 Main 服务隔离系统权限，降低命令注入和越权风险。 |
| 预设优先 | 普通用户不需要理解 CRF、编码器和码率即可完成转换。 |
| 自建 CSS 设计令牌 | 精确控制 960 × 640 桌面布局并减少样式依赖；该项替代原方案中的 Tailwind。 |
| 顺序队列 | 视频编码通常占用大量计算资源，顺序处理更稳定、可预测。 |
| 临时输出 + ffprobe 校验 | 防止残缺文件被误认为转换成功，并支持失败清理。 |
| 不静默覆盖 | 自动生成 `-converted-2` 等安全文件名，保护用户已有文件。 |
| 浏览器模拟 API | 在 Electron 运行时尚未下载完成时，仍可用同一 React 界面做可靠的交互和视觉回归。 |
| preload 固定为 CommonJS | Electron 沙箱 preload 不直接支持当前 ESM 输出；显式使用 `index.cjs` 可保证桥接稳定加载。 |
| 正式包只读 `resources/bin` | 成品不依赖 `node_modules` 中的开发工具路径，安装后可独立运行。 |
| 未签名 v0.1.0 包 | 当前没有代码签名证书；先完成可复现 MVP 验收，并明确保留 Windows 信誉提示这一限制。 |
| Main 强制并发数为 1 | UI 原本已经串行，但 Main 不能信任 Renderer；并发闸门作为独立安全边界。 |
| 移除通用 `openPath` | 当前产品只需要定位转换结果，不应给 Renderer 打开任意本地路径的能力。 |
| 保留缩略图快速 seek | 缩略图用于快速识别素材，响应速度比精确到帧更重要；专业截图以后作为独立功能。 |
| 不做强制黑屏检测 | 黑屏可能是合法内容，自动 `blackdetect` 会误报；v0.1.0 校验结构完整性而非内容语义。 |

界面验收过程中发现固定底部操作栏在低窗口高度下会错位。已将可选工具错误提示改成显式网格状态，并统一低高度操作栏轨道与最小高度；复验后操作栏底边精确位于 640 px。

真实 Electron 运行验收中发现 preload 配置引用了错误扩展名，且 ESM preload 无法在当前沙箱加载环境中执行，导致界面错误地使用了浏览器模拟 API，“添加”和“选择文件夹”不会调用系统对话框。现已将 preload 固定构建为 CommonJS `index.cjs`、修正 Main 引用，并禁止 Electron 环境静默使用模拟 API。复验确认真实 `window.frameFlow` 已加载，FFmpeg 6.1.1 和 ffprobe 状态正常。

## 6. 当前限制与风险

- v0.1.0 未配置 Windows 代码签名，首次运行可能显示“未知发布者”或信誉提示。
- 为绕过当前 Windows 构建环境对 electron-builder 辅助包符号链接的权限限制，关闭了可执行文件资源编辑，因此仍使用默认 Electron 可执行文件图标；不影响应用内已完成的 FrameFlow 品牌界面。
- 自动化验收验证了对话框 IPC 全链路，但用可控返回值替代了操作系统对话框内的人工选取；安装、卸载和系统信誉提示需要在目标验收机人工确认。
- 内容语义级黑屏、静音检测未启用，避免把合法黑场或静音片段误判为失败；当前保证的是容器与媒体流结构完整性。
- 正式大范围分发前仍应核对 FFmpeg 构建的许可证及编解码器配置，并补充代码签名、品牌图标与完整第三方许可证清单。
- 项目位于公开仓库 `https://github.com/1502773238/Video-format-converter` 的 `main` 分支。
