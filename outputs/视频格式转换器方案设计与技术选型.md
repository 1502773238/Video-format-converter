# 视频格式转换器：方案设计与技术选型

> 文档状态：方案已选定，MVP 已进入实现与验收  
> 日期：2026-10-14  
> 暂定产品名：FrameFlow（后续可更名）

## 1. 结论

本项目做成一个真正的 Windows 桌面客户端，不做网页套壳演示，也不把 FFmpeg 命令直接暴露给普通用户。

首版技术栈选择：

- 桌面容器：Electron
- 界面：React + TypeScript + Vite
- 样式：CSS 设计令牌 + 自建轻量组件规范（不引入运行时样式依赖，便于精确控制桌面窗口布局）
- 状态管理：Zustand
- 媒体分析：`ffprobe` 命令行，JSON 输出
- 缩略图与转码：`ffmpeg` 命令行
- 打包：electron-builder，首版输出 Windows x64 安装包和免安装版
- 测试：Vitest + React Testing Library + Playwright Electron 冒烟测试

核心产品原则：默认设置让普通用户可以在 3 步内完成转换；高级参数折叠起来，不要求用户理解编码器、CRF、码率等概念。

## 2. GitHub 参考项目与吸收点

### 2.1 LosslessCut

项目：https://github.com/mifi/lossless-cut

吸收：

- Electron 桌面架构和 FFmpeg 子进程管理方式。
- 不依赖浏览器原生解码能力生成缩略图，而是用 FFmpeg 截帧。
- 长耗时任务支持进度、取消和错误反馈。
- 媒体能力与界面分层，渲染进程不直接获得任意命令执行权限。

不照搬：

- LosslessCut 的核心是无损剪切，当前项目聚焦格式转换，不引入时间线编辑。
- 不做过多专业菜单，避免首屏认知负担。

### 2.2 FFUI

项目：https://github.com/muyuanjin/ffui

吸收：

- “任务队列 + 预设”的主工作流。
- 拖拽添加、结构化媒体信息、输入输出对比、单任务日志。
- 首次启动检查 FFmpeg，允许自动配置或手动选择路径。
- 转换完成后保留可核验的输出信息。

不照搬：

- 首版不做 VMAF、系统性能大盘、目录自动扫描等重功能。
- 不采用 Tauri/Rust；当前工作区没有 Rust/Cargo，首版引入会增加构建和调试风险。

### 2.3 HandBrake

项目：https://github.com/HandBrake/HandBrake

吸收：

- 面向普通用户的用途预设，而不是先让用户选一串技术参数。
- 明确的“打开源文件 → 选预设 → 选择输出 → 开始”流程。
- 批量任务队列和任务完成后的清晰状态。

不照搬：

- 不复制 HandBrake 的密集设置页；高级设置采用渐进披露。
- 首版只覆盖常见转换场景，不做光盘、章节、复杂字幕编辑。

### 2.4 Comet / 其他 Electron FFmpeg 项目

项目：https://github.com/Thavarshan/comet

吸收：Electron + Vue/React 类前端与 FFmpeg/ffprobe 配合的可行性。

不照搬：不会把项目做成只有格式下拉框和开始按钮的演示页；必须补齐缩略图、媒体信息、真实进度、取消、输出校验和可用错误提示。

## 3. 客户端框架选型

| 方案 | 客户端属性 | UI 开发效率 | FFmpeg 进程管理 | 安装包体积 | 当前交付风险 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| Electron + React | 强 | 高 | 高 | 较大 | 低 | **首选** |
| Tauri 2 + React | 强 | 高 | 高 | 小 | 中高（需 Rust） | 后续轻量化候选 |
| C# + WPF/WinUI | 最强 Windows 原生感 | 中 | 高 | 中 | 中 | 仅适合确定只做 Windows 时 |
| 浏览器 Web App | 弱 | 高 | 受限 | 无安装包 | 中 | 不满足本项目评审重点 |

### 为什么首版选择 Electron

1. 它是明确的桌面客户端方案，支持原生文件对话框、拖放、本地文件、托盘/通知和打开输出目录。
2. Node 主进程可直接、稳定地管理 `ffmpeg` / `ffprobe` 子进程，解析 stdout/stderr 并处理取消。
3. 当前环境已有 Node 与 pnpm，缺少 Rust、Cargo、FFmpeg、ffprobe 和 GitHub CLI。选择 Electron可以减少一整层工具链风险。
4. FFmpeg 本身会显著增加分发体积，因此 Tauri 节省的壳体体积不是首版最重要的指标。
5. React 生态适合快速完成高完成度界面、状态管理和自动化测试。

代价是安装包较大、运行内存高于原生方案。对桌面视频工具而言可接受，后续如果确有轻量化需求，再评估 Tauri 迁移。

## 4. 产品定位与界面方案

### 4.1 目标用户

- 不懂 FFmpeg、只想把视频转成可播放格式的普通用户。
- 需要批量转换、查看进度和失败原因的内容创作者。
- 懂编码参数、希望微调编码器/质量/分辨率的进阶用户。

### 4.2 主界面

采用单窗口“工作台”布局，默认窗口建议 1180×760，最小 960×640。

```text
┌──────────────────────────────────────────────────────────┐
│ FrameFlow                         设置     最小化 关闭   │
├───────────────┬──────────────────────────────────────────┤
│               │ 文件名、时长、体积、分辨率、帧率         │
│  视频缩略图    │ 编码：H.264   音频：AAC   容器：MP4      │
│  16:9 预览区   ├──────────────────────────────────────────┤
│               │ 转换为  [通用 MP4 ▼]                     │
│  更换文件      │ 质量    [推荐 ─────●────]                │
│               │ 分辨率  [保持原尺寸 ▼]                   │
├───────────────┴──────────────────────────────────────────┤
│ 输出到  D:\Videos\output.mp4             [选择文件夹]   │
│ [高级设置]                         [加入队列] [开始转换] │
├──────────────────────────────────────────────────────────┤
│ 任务队列  旅行.mov → 旅行.mp4  ███████░░ 73%  1.8x      │
└──────────────────────────────────────────────────────────┘
```

空状态时显示大面积拖放区：

- 主文案：“把视频拖到这里”
- 次操作：“或选择视频文件”
- 辅助文案：支持 MP4、MOV、MKV、AVI、WebM 等 FFmpeg 可读取格式

### 4.3 视觉方向

- 定位：专业但不压迫，避免传统工具软件的密集表单感。
- 默认深色主题，搭配中性色面板与青蓝色主操作色；同时支持浅色主题。
- 转换主按钮始终只保留一个明确主操作，危险操作使用红色且二次确认。
- 信息展示使用“人能读懂”的文本，例如 `1920 × 1080`、`2 分 14 秒`、`126 MB`，技术原值放在详情中。
- 所有状态不只依靠颜色：同时显示图标和文字，兼顾色觉差异。

## 5. 功能范围

### 5.1 MVP 必须完成

1. 点击选择或拖拽加载单个/多个视频。
2. 调用 `ffprobe` 获取容器、时长、体积、分辨率、帧率、视频编码、音频编码、码率、音轨数量。
3. 调用 `ffmpeg` 截取缩略图并显示；失败时提供占位图，不阻塞转换。
4. 提供四个普通用户预设：
   - 通用 MP4：H.264 + AAC，兼容性优先。
   - 高压缩 MP4：H.265 + AAC，体积优先。
   - WebM：VP9 + Opus，网页使用。
   - 仅提取音频：MP3。
5. 可选择输出目录，自动生成安全文件名并处理重名。
6. 显示真实转换进度、已用时间、估算剩余时间和速度。
7. 支持暂停队列、取消当前任务、失败重试。
8. 转换完成后用 `ffprobe` 校验输出文件可读且时长合理。
9. 提供“打开文件”“打开所在文件夹”“查看日志”。
10. 转换过程离线完成，不上传用户视频。

### 5.2 首版优化项

- 批量任务队列，默认串行执行，避免多任务同时抢占 CPU/GPU。
- 记住最近的输出目录、主题和最后使用的预设。
- 转换前检查预计输出路径、可用磁盘空间和覆盖风险。
- 根据源视频自动推荐预设；例如源文件已是兼容 MP4 时提示无需重复转码。
- 高级设置中展示“生成的 FFmpeg 参数”，但默认只读，便于评审和排错。
- 支持导出诊断日志，日志自动去除完整用户路径等隐私信息。

### 5.3 暂不进入首版

- 视频剪辑时间线、滤镜、水印、字幕编辑。
- 登录、云同步、视频上传。
- VMAF 质量评分和复杂性能监控。
- 插件系统。

控制范围能保证核心体验真的经过测试，而不是功能很多但每项都不可用。

## 6. FFmpeg / ffprobe 设计

### 6.1 媒体信息

示例参数：

```text
ffprobe -v error -print_format json -show_format -show_streams -show_chapters INPUT
```

解析时不能假设字段一定存在；帧率 `r_frame_rate` 需要按分数解析，时长和码率需要容错。界面优先显示第一条默认视频流和默认音频流，其余流放入“更多信息”。

### 6.2 缩略图

截帧时间取视频时长的 10%，并限制在 1～10 秒；极短视频退化到 0 秒。建议参数：

```text
ffmpeg -ss TIMESTAMP -i INPUT -frames:v 1 -vf scale=640:-2 -q:v 3 -y THUMBNAIL.jpg
```

缩略图写入应用缓存目录，任务删除或缓存过期时清理。需要处理旋转元数据、无视频流、封面流和损坏文件。

### 6.3 转换进度

使用 FFmpeg 的机器可读进度，不解析面向人的动态日志文本：

```text
ffmpeg -nostdin -y -i INPUT ...OUTPUT_ARGS... -progress pipe:1 -nostats TEMP_OUTPUT
```

通过 `out_time_ms / duration` 计算进度，通过 `speed` 显示速度。输出先写临时文件，校验成功后再原子重命名为最终文件，避免把中断的半成品误认为成功结果。

### 6.4 进程安全

- 使用参数数组启动进程，不拼接 shell 字符串，避免文件名中的空格、引号或特殊字符导致错误。
- FFmpeg 只由 Electron 主进程启动；渲染进程只能通过预定义 IPC 方法请求分析、转换、取消和打开目录。
- `contextIsolation: true`，`nodeIntegration: false`，preload 仅暴露窄接口。
- 任务取消后等待进程结束，清理临时输出；最终文件绝不静默覆盖。
- 对 ffprobe 设置超时，对错误输出设置内存上限并落盘保存完整日志。

## 8. FFmpeg 分发策略

对最终用户不能只提示“请自己配置环境变量”。建议顺序：

1. 应用先检查内置工具目录。
2. 再检查用户在设置中指定的目录。
3. 最后检查系统 PATH。
4. 全部找不到时，显示带解释的配置向导，支持下载经过校验的版本或手动选择。

仓库不直接提交大型二进制。构建脚本下载固定版本并校验 SHA-256；Release 安装包可携带可再分发的 FFmpeg/ffprobe，同时附带 `THIRD_PARTY_NOTICES.md`、许可证和构建来源。正式分发前必须根据所选 FFmpeg 构建变体复核 LGPL/GPL 义务。不能无意间使用滚动 `latest` 导致构建不可复现。

## 9. 错误体验

错误提示必须告诉用户“发生了什么”和“下一步怎么做”，不能只弹 `Exit code 1`。

示例：

- 无法读取视频：文件可能损坏或格式不受支持；可展开查看技术日志。
- 输出目录空间不足：显示所需估算空间和当前可用空间，并提供更换目录按钮。
- 输出文件已存在：提供“自动重命名”“替换”“取消”，默认自动重命名。
- 编码器不可用：自动回退到软件编码或建议切换预设。
- 用户取消：状态显示“已取消”，不显示为“失败”。

## 10. 测试与验收

### 10.1 测试素材矩阵

- MP4 / H.264 / AAC，横屏 1080p。
- MOV，包含旋转元数据的竖屏视频。
- MKV，多音轨或字幕轨。
- WebM / VP9 / Opus。
- 3 秒以内的极短视频。
- 中文、空格、括号、emoji 文件名与长路径。
- 损坏文件、无音轨文件、只含封面或无视频流文件。

测试素材使用可再分发的小文件或在测试中由 FFmpeg 合成，不把私人视频提交到仓库。

### 10.2 验收标准

- 新用户从启动到开始转换不超过 3 个主要动作。
- 加载正常视频后能在 2 秒级时间内显示基本信息和缩略图（以小型本地测试文件为准）。
- 进度单调递增，完成时为 100%，取消后不残留假成功文件。
- 输出能被 ffprobe 重新读取，格式/编码符合所选预设，时长误差在合理范围。
- 中文和特殊字符路径可正常处理。
- FFmpeg 缺失时出现配置引导，而不是应用崩溃。
- 至少完成一次安装包冷启动实测，而不只测试开发模式。

- Release：安装包、免安装版、SHA-256、已知限制。

GitHub 提交前检查：不提交私人视频、缓存、日志、FFmpeg 大型二进制、密钥或机器绝对路径。

1. 搭建 Electron/React 安全骨架，做出高完成度静态界面。

10. 创建 GitHub 仓库、推送代码、运行 CI、创建 Release，最后把项目链接回传。

## 14. 开工前置条件

当前机器检查结果：Node、pnpm、git 可用；FFmpeg、ffprobe、Rust/Cargo、GitHub CLI 未发现。

进入实现前需要：

- 下载固定版本的 FFmpeg/ffprobe 到项目工具目录，记录来源与校验值。
- 安装项目依赖。
- GitHub 发布阶段准备仓库归属、仓库可见性和登录授权；这些属于外部状态，不能在方案阶段自行假设。
